# The Shattered Crown — GBA JRPG (Milestone 1)

An original turn-based RPG built as a genuine Game Boy Advance ROM in C.
No external libraries: just devkitARM, a hand-written hardware header, and
content defined as data tables.

## Platform and constraints

- **Target:** real GBA ROM (240×160, mode 0 tile backgrounds, 4bpp tiles, hardware sprites).
- **Toolchain:** devkitARM via the `devkitpro/devkitarm` Docker image on GitHub Actions.
- **Play:** any GBA emulator (iOS: Delta, etc.).
- **Hardware rules respected:** 16-bit-only VRAM writes, OAM updated from a shadow
  copy during VBlank, BG scroll applied in VBlank, all art in 16-colour palette banks.

## Build (from iPhone or anywhere)

1. Create a new GitHub repo and upload every file from this folder to the repo root
   (Add file → Upload files; you can multi-select).
2. Create `.github/workflows/build.yml` (Add file → Create new file, type that path)
   and paste in the contents of `build.yml`.
3. Each push builds the ROM. Open **Actions → latest run → Artifacts →
   shattered-crown-rom**, unzip, and open `shattered_crown.gba` in your emulator.

Local build with devkitPro installed: `make`.

Art and maps are generated by `gen_assets.py` (needs Python 3 + Pillow) into
`assets.c` / `assets.h`. Those generated files are committed, so the ROM build
never needs Python. Re-run the script only when changing art or map layouts.

## Controls

| Button | Field | Menus / text |
|---|---|---|
| D-pad | Walk | Move cursor |
| A | Talk / examine | Confirm / advance text (also skips typing) |
| B (hold) | Run | Cancel / advance text |
| Start | Open menu | Skip prologue |

## Architecture

```
main.c        boot → title → prologue → field loop
platform.c    video init, frame pacing (VBlank), input + key repeat, OAM shadow, fades, RNG
text.c        BG0 text layer: window boxes, typewriter dialogue with auto word-wrap and
              paging, generic vertical menus, yes/no prompt, full-screen narration
field.c       BG1 map renderer (16×16 metatiles on a 64×64 tile background), camera,
              grid movement for player + NPCs, collision, NPC wandering, interaction
              (including talking across counters), page-based event scripts, warps
menu.c        title screen, options, field menu, status screen, item screen
state.c       GameState, story flags, inventory, party stat generation
audio.c       square-wave SFX sequencer (channel 2); music hook reserved for channel 1
data_game.c   characters, spells, items, enemies, experience curve
data_maps.c   maps, NPCs, events, warps, Chapter 1 dialogue and prologue
assets.c/.h   GENERATED tiles, palettes, metatiles, map grids, sprites, title art
gen_assets.py asset generator; font5x8.py is the original 5×8 font
```

**VRAM layout:** BG0 (text, priority 0) uses charblock 0 + screenblock 30.
BG1 (map/title, priority 2) uses charblock 1 + screenblocks 26–29 (64×64).
Sprites (priority 1) are 16×32 with 1D mapping. Palette banks: 0–3 UI,
4 exterior, 5 interior, 6 title.

## Core data models (data.h)

- `CharacterDef` – base stats, growth rates (tenths per level), learn list, sprite.
- `PartyMember` – runtime level, EXP, HP/MP, stats, status bits, equipment slots.
- `SpellDef`, `ItemDef`, `EnemyDef` – combat content, element weak/resist masks.
  Items flagged `IFLAG_KEY` can never be sold or dropped.
- `MapDef` → `NpcDef`, `EventDef`, `WarpDef`. NPCs and events run a `Script`:
  a list of `Page`s. The highest page whose condition flag is set runs, then raises
  its `set` flag and performs its `action`. This drives all conditional dialogue.
- `GameState` – party, gold, inventory, 256 story flags, location, settings.
- `SaveFile` – magic + version + checksum wrapper for SRAM (used in Milestone 3).

## Milestone status

**Milestone 1 — complete**
- Title screen (New Game / Continue placeholder / Options)
- Skippable prologue narration
- Brindleford village (30×20) and the Kettle & Key inn interior, with door warps and fades
- Grid movement, running, collision, camera clamping, Y-sorted sprites, 4-direction walk animation
- 7 NPCs (static and wandering) who turn to face you; 8 examinable events; tile examine fallbacks
- Typewriter dialogue with word wrap, paging, name substitution, 4 text speeds
- Flag-driven mini story: Elder → mill rubble → Star Shard → Elder's revelation → inn rest → dream → end card
- Field menu: Status, Items (scrolling list + descriptions), Options, Save placeholder
- Inn yes/no prompt and full heal; sound effects for cursor, confirm, cancel, item, door, rest

**Data already defined for later milestones:** 5 characters, all 14 spells with
learn levels, 16 items, 6 enemies, 35-level EXP curve, save file format.

**Not yet built:** combat (M2), shops (M2), recruitment and party management (M3),

## Known limitations

- VBlank is a busy-wait on VCOUNT; switching to the BIOS `VBlankIntrWait` with an
  interrupt handler (lower power on real hardware) is planned for Milestone 2.
- Maps are capped at 32×32 metatiles because each one is drawn whole into a
  64×64 background. The overworld (Milestone 5) needs a streaming renderer.
- The font is fixed-width (8 px per character).
